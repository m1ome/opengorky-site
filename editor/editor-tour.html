    Field manual / Level editor

    Editor tour

    What each part of the editor window does: the asset tree, the pages for every kind of asset, the level tools, the code editor and the checks.

    The window

    • Asset tree on the left, searchable. Assemblies (locations, battles, characters, items, scenes), components and raw assets (sounds, sprites, fonts…), and the project itself. Right-click to copy, paste or create.
    • Centre: the open document, one tab each.
    • Toolbar: Play, Fit, and the unsaved/saved state.
    • Status bar: the project kind, the last action and the mod check's problem count.

    Locations and battles

    A level opens as its map with tool panels:

    • Objects: drag items, fighters, boxes and props. Right-click the map or a row to add an enemy, a hero, a box, an item or a prop, edit a box's contents or remove something. Delete removes the selected object. In battles, enemies can walk in at the start or stand on their tile, and props turn by the arrows next to them.
    • Painting: the map's layers (walkable floor, areas, lights), painted with a brush. Each stroke is one undo step. A locked layer must be unlocked first.
    • Paths, camera, lights, areas and triggers: the level's routes (stairs, ladders), view, lighting, zones and what happens in them.

    New levels can start from a blank picture: 640×480 to 2600×1916 in Classic, up to 8192×8192 in an OpenGorky project, in multiples of 8.

    Characters, weapons and items

    Values on a class page apply to every such enemy or item in the game. A battle's own values for one enemy override them. Make a copy creates a new class, weapon, item, ammo or hero, and the page explains what the copy shares with the original. Models import from .glb and textures from PNG. Strikes, projectiles and effects are edited on their own pages. A test room puts a fighter into a hidden battle so you can try it. The test kit sets what the heroes carry there.

    Scenes, texts and media

    • Scenes and dialogue: command lists and dialogue lines. A scene can be switched off.
    • Texts: every game string. The editor warns when the game's code page or font lacks a character.
    • Sounds and music: import WAV or MP3. The editor converts them to the game's format.
    • Videos: import any video FFmpeg reads. Classic converts it to the game's ASF, an OpenGorky project keeps it as is.
    • Fonts: draw missing characters from a TrueType font. Sprites and effects: paint, or import PNG frames.

    Game, rules and interface

    In an OpenGorky project, the campaign page sets the new game, party, videos, music, experience, formulas and fighter states, plus the hooks of src/game.ogs. Rules pages cover experience levels, special values, AI profiles and actions. The interface page covers the main menu, windows and panel. The engine's tuning values (adjust.kdt, or rules/settings.ogs in a project) have their own page.

    Code editor

    Scripts open in a code editor with completion, hints and checks. Shortcuts:

    Ctrl+Spacecomplete
    Tabnext argument
    F12 / Cmd+clickgo to definition
    Shift+F12find usages across the game's scripts and rules
    F1the Reference article for the word under the cursor
    Cmd+Ffind
    Cmd+/comment
    Alt+↑/↓move lines
    Cmd+Shift+Kdelete line
    Cmd+Shift+Zredo

    Saving, history and checks

    • Ctrl+S saves. Ctrl+Z undoes any step until you quit, including deletions.
    • History lists past saves. Restoring one brings back its files as unsaved changes, which you can review and save again.
    • The mod check looks for anything the game would stumble on: archives, scripts (#include, #inherit), models and textures, LEVEL_Load targets. It reads the folder as saved, so save first.
